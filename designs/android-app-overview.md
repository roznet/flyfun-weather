## Implementation Status

All four core phases are built and verified against both offline fixtures (`FLYFUN_MOCK=1`) and the live local HTTPS backend (`https://localhost.ro-z.me:8443`), with two explicit follow-ups noted below:

- **Phase 0 (Server & CI)**: `device_tokens.platform` (`"ios"` | `"android"`, migration `110`), `FcmPushSender` in `src/weatherbrief/notify/push.py`, `/.well-known/assetlinks.json` in `deploy/weather.flyfun.aero.caddy`, and `.github/workflows/android.yml` + `android-ui-nightly.yml` (runs JVM unit tests across all 4 modules, Android lint, and debug APK compilation).
- **Phase 1 (Core App & App-Local Pure-JVM Libraries)**: `:flyfun-common`, `:rzflight`, Auth (`AndroidTokenStore` backed by Android Keystore AES-GCM), Adaptive Flight List & Trips, Add/Edit Flight, Aircraft CRUD, Advisory & Discussion tabs (with Surface Charts + GRAMET PDF/PNG), Offline `/bundle` & 50 MB Chart Cache in `filesDir/BriefingCache`, What's New, and Feedback.
- **Phase 2 (Cross-Section, Route Graph & Skew-T)**: `:rzskewt` thermodynamics & transform library, 17+ layer `CrossSectionCanvas` (with `Square`/`Soft`/`Natural` cloud styles and Web-aligned `thermo-convective-bg` + axes), phone-first `LayerBarView` (integrated model pills + `Focus` preset + pinned `Options` sheet + wrapping `FlowRow` of all 7 canonical `LayerFamily` chips), pixel-aligned `RouteGraphCanvas` with single-row L/R metric controls, and interactive `SkewTCanvas` with dual-axis side panel and Compare Models mode.
- **Phase 3 & 4 (Maps, Observed Tab, In-Flight GPS, PIREPs & Push Plumbing)**: Web Mercator `SlippyMapCanvas` (Stadia dark/muted + OSM light tiles with 30 MB OkHttp disk cache), `RouteMapTabScreen`, `PanEuropeanMapScreen` (Forecast + Historical Replay), flight-day `ObservedTabScreen` with `RouteRibbonCanvas` and `RunwayWindDialView`, `FlightTrackingService` (foreground location service wired to `ObservedTabScreen`), `PirepOfflineStore`, and `PushNotificationManager`.
- **Not yet bundled / deferred**:
  - **Firebase Cloud Messaging (FCM) client SDK**: Server-side `FcmPushSender` (`notify/push.py`) and client-side `PushNotificationManager` (notification channel, Android 13+ permission check, `POST /api/devices` registration, foreground suppression, and tap deep-linking) are implemented, but `com.google.firebase:firebase-messaging` and `google-services.json` are not yet added to `:app`. Until a Firebase project is provisioned and a `FirebaseMessagingService` forwards the FCM token to `PushNotificationManager.registerDeviceToken`, remote push notifications are inactive on Android devices.
  - **Instrumented emulator tests (`androidTest`)**: Automated tests currently run as fast JVM unit tests (`./gradlew test :app:testDebugUnitTest`). Compose UI instrumentation tests (`src/androidTest/`) are not yet configured in CI.

## What's Built

### Authentication (`ui/auth/LoginScreen.kt`, `:flyfun-common`)
- Driven by `FlyFunAuthService` (`aero.flyfun.common`):
  - **Sign in with Google**: Chrome Custom Tabs OAuth (`/auth/login/google?platform=ios&state=<nonce>`) → `flyfunweather://auth/callback?code=...&state=...` → `POST /auth/exchange`. *(Note: `AuthConfig.platform` intentionally defaults to `"ios"` because upstream `flyfun-common` on the server branches on `platform == "ios"` to emit custom-scheme `flyfunweather://auth/callback` redirects instead of setting a web cookie.)*
  - **Sign in with Email**: magic-link request (`POST /auth/magic-link`) + code verification sheet.
  - **Dev Login**: `GET /auth/dev-token` in debug builds on the Android Emulator (`BuildConfig.DEBUG && ApiClient.isRunningOnEmulator()`), connected to `https://localhost.ro-z.me:8443` (real devices connect to `https://weather.flyfun.aero`).
  - **Demo Mode (`Try Demo Mode`)**: switches `AppStateViewModel` to `FixtureBriefingRepository` + `FixtureTripRepository` so the full app can be explored offline without a server.
- Session JWT is encrypted at rest via `AndroidTokenStore` (`data/AndroidTokenStore.kt`, using Android Keystore `AES/GCM/NoPadding` 256-bit key in `filesDir/flyfun_auth_token.enc`, with automatic migration from legacy plaintext tokens) and rotated automatically via host-scoped `RollingBearerInterceptor` whenever the configured API server returns `X-Renewed-Token`.
- Reviewer deep-link carve-out (`JwtClaims.shouldAcceptDeepLinkToken`) accepts a bare token in a deep link only when signed out and the token payload carries `"scope": "review"`.

### Flight List & Trips (`ui/flights/`, `ui/trips/`)
- **Adaptive two-pane layout** (`MainActivity.kt`, `FlightListScreen.kt`): on wide tablets/foldables (`maxWidth >= 840.dp`), renders a persistent 360dp flight list pane alongside the detail `BriefingContainerScreen`; on phones (`< 840.dp`), uses single-pane stack navigation with `rememberSaveable` state preservation across rotation and root `BackHandler` support.
- **Flights vs. Trips toggle**: switches between duration-aware collapsible sections (`Future`, `Recent`, `Past`) and multi-leg `Trips` (`TripDetailScreen.kt`: conjunctive chain status, binding leg callout, Haiku trip summary, per-leg cards, and serial trip refresh).
- **Multi-select bulk delete**: long-pressing a flight row or choosing `Select & Delete Flights` from the top bar enters contextual multi-select mode (`POST /api/flights/bulk-delete`).
- **Top bar actions**: quick `Explore Maps` button (opens `PanEuropeanMapScreen`), `+` Add Flight FAB, and `More` menu (`My Aircraft`, `What's New` with unseen badge dot, `Settings`, `Send Feedback`, `Sign Out`).

### Add / Edit Flight & Aircraft (`ui/flights/AddFlightSheet.kt`, `ui/aircraft/`)
- Offline ICAO route autocomplete backed by `AirportDatabaseService` (`GET /api/nav/airports-db` with ETag caching) and `:rzflight`'s `KnownAirports.rankedSearch`.
- Native Material 3 date (`DatePickerDialog`, UTC) and 24-hour time (`TimePicker`/`TimeInput` with `:00/:15/:30/:45` chips applied on OK) pickers, an hours + quarter-hour `FlightDuration` picker with a synced slider, cruise altitude & ceiling inputs with live aircraft service-ceiling warning (`AddFlightViewModel.ceilingWarning`, #777), Autorouter route import, and structural edit detection (prompting **Move** vs. **Duplicate** when route or date changes).
- Full aircraft registry CRUD (`AircraftListScreen.kt`, `AircraftFormSheet.kt`) with Make Default and 409 last-aircraft deletion guard.

### Briefing Viewer (`ui/briefing/BriefingContainerScreen.kt`)
- **Leading Pack Toolbar (`BriefingPackToolbar.kt`)**: displays freshness dot, `D-N` label, assessment badge, and offline cache icon; dropdown switches historical packs, triggers `Download for Offline` (`/bundle`), or starts an SSE streaming `Refresh Briefing` (`POST /packs/refresh/stream`). Opening a flight with no pack (the normal state after `POST /api/flights`) starts the first briefing, unless `/packs/refresh/status` shows a run already in flight (web, another device): then `pollActiveRefresh` follows it (3 s, 100-poll cap, like iOS `checkActiveRefresh`) with the same banner, and reports an error if it ends with no pack. A pack already on screen gets the same background follow and is only reloaded if the run produced a newer one. If the SSE stream drops before `complete` (screen off, app backgrounded), `refreshBriefingInternal` asks `/refresh/status`: an active or unknown (failed check) run is followed by polling; otherwise a newer `latestPack` or a `briefing_ready` provisional pack is adopted. `ApiClient.refreshPackStream` maps only non-2xx responses to `ApiError.ServerError`; a mid-stream drop on a 200 is a `NetworkError`. `BriefingContainerScreen` keeps the screen on while refreshing and calls `onForegroundResume` on `ON_RESUME` (not the initial one), which re-attaches to an active run or adopts a newer pack, with up to 3 retries when the screen needs recovery; a user refresh cancels that job. All 9 pack sub-endpoints load concurrently via `coroutineScope { async { ... } }` in `BriefingViewModel`.
- **5-Tab Navigation (`BriefingTab.tabs(showsObserved)`)**:
  1. **Advisory (`AdvisoryTabScreen.kt`)**: sticky `SectionSpyBar`, accented Verdict Hero card, flight-day `ObservedTeaserRow`, digest altitude warning, digest 👍/👎 feedback, post-flight `DebriefCard`, responsive `AMBER`/`RED` `AdvisoryCard`s with `FocusIntent` deep links (`View on Cross-Section ›`, `View on Map ›`), collapsible `GreenAdvisoryStrip`, departure/destination `AirportConditionsSection`, EASA/FAA `AlternatesSection`, and `TimingScenariosSection`.
  2. **Discussion (`DiscussionTabScreen.kt`)**: sticky `SectionSpyBar` (`Synoptic`, `Charts`, `Concerns`, `Trend`, `Watch`, `GRAMET`), `MarkdownLiteText` sections, `SurfaceChartsSection.kt` (DWD / Met Office / TEMSI source & time chips + Compose `Canvas` route overlay + pinch-to-zoom dialog), and `GrametSection.kt` (renders PDF via Android's native `PdfRenderer` or PNG via `BitmapFactory`, plus Coil `io.coil-kt:coil-compose` for image loading).
  3. **Cross-Section (`ui/crosssection/CrossSectionTabScreen.kt`)**: phone-first `LayerBarView.kt` (row 1 integrates segmented `GFS | ECMWF | ICON` model pills, `Focus` preset dropdown, active `Emulate`/`Theme` indicators, and a pinned `Options` bottom-sheet button; row 2 wraps all 7 canonical `LayerFamily` chips — `Clouds`, `Convection`, `Icing`, `Turbulence`, `Levels`, `Stability`, `Observed` — with inline expandable sub-strips and `Square`/`Soft`/`Natural` cloud style controls), cockpit `CrossSectionReadoutBar.kt` (with `Sounding ›` quick-scroll pill), 17+ layer `CrossSectionCanvas.kt` (outer card margin + inner `#7395DB` sky plot rect, altitude/pressure/waypoint/distance/UTC axes, Web-aligned `thermo-convective-bg`, and directional scrub-vs-scroll gesture lock), pixel-aligned `RouteGraphCanvas.kt` (14 metrics, dual Y-axes with rotated unit labels, `AboveScale` chevrons, and single-row `[▲ Graph] [L: ▾] [R: ▾]` controls), and inline `SkewTDetailSection.kt` (`SkewTCanvas.kt` with CAPE/CIN fill, parcel path, multi-model compare mode, 14 side-panel variables, and bidirectional altitude hover sync). Presets mirror Web `advisory-presets.ts` / `layer-registry.ts`: `Basic / Learn` shows one layer per method group on its preferred method — NWP convection (`convective-nwp`), which `NwpFallback` swaps for Thermo where the model has no native convective field. iOS `CrossSectionPresets.swift` / `LayerFamily.swift` follow the same 7-family, one-per-method-group model.
  4. **Map (`ui/map/RouteMapTabScreen.kt`)**: interactive Web Mercator `SlippyMapCanvas.kt` with Stadia `alidade_smooth_dark` (dark mode), Stadia `alidade_smooth` (muted light mode under radar/satellite overlays), and OpenStreetMap (standard light mode) raster tiles cached via OkHttp, 13 route segment metrics, altitude slider, wind barbs, Hewson fronts, SIGMET polygons, OPERA radar / IR satellite tile overlays, storm cell contours (`20/35/41 dBZ` + 30-min motion vectors), age-faded lightning bolts (`⚡`), alternate airport detour lines, and tap inspector with `Open Skew-T at this point ›`.
  5. **Observed (`ui/observed/ObservedTabScreen.kt`)**: appended on the right on flight day (`hasObservedContent`) and auto-selected once when opening a flight inside the live window (`departure − 3h … arrival + 1h`). Renders the live status & GPS tracking bar (requesting runtime location permissions and starting/stopping `FlightTrackingService`, with a manual scrub slider in Demo Mode), `ObservedHighlightCard` (Haiku alert lines + 👍/👎 rating), `ObservedNutshellCard` + interactive 4-lane `RouteRibbonCanvas` (Radar VIP, Lightning, SIGMETs, Stations + live GPS aircraft progress marker), `LiveChangesSection` (with expandable history trails), `LiveStormsSection` (with 30-min off-track distance sparkline), `RouteObservationsSection` (with `obs_proxy` badges and Compose `Canvas` `RunwayWindDialView` compass/runway dials), and `RouteSigmetsSection`.

### Pan-European Forecast & Historical Maps (`ui/map/PanEuropeanMapScreen.kt`)
- Accessible from the Flight List top bar (`Explore Maps`) or `/maps.html` deep links.
- Switches between **Forecast Map** (`D-0`..`D-6`, UTC hours, model selector, 10 airport metrics from `HelpCatalogStore`, tappable `ForecastAirportCard` bottom sheet) and **Historical Replay** (past UTC date + 30-min slider, lead selector, `HistoricalAirportCard` comparing actual METAR vs. TAF vs. archived model forecast).

### In-Flight GPS Service, Offline PIREPs & Push (`service/`, `data/PirepOfflineStore.kt`)
- **`FlightTrackingService.kt`**: Android `foregroundServiceType="location"` service (`START_STICKY`) with compact ongoing notification, invoked from `ObservedTabScreen` after runtime location permission grant (`ACCESS_FINE_LOCATION` / `ACCESS_COARSE_LOCATION`). Projects GPS fixes onto the active route via `LivePositionRules.projectOntoRoute` and posts sparse updates (`POST /api/flights/{id}/live/position` when $\Delta t \ge 3\text{ min}$, $\Delta d \ge 8\text{ NM}$, or $\Delta alt \ge 800\text{ ft}$), at most 5 fixes a post (the server's limit). The fix JSON is the server's `LivePositionFix` (`at`, `alt_ft`, `gs_kt`, `track_deg`, required `h_accuracy_m`; a missing value is omitted, never 0, which the server would read as on the ground); before #874 it used other field names and a nonexistent `/api/live-position` fallback, so no Android fix ever reached the server. Landing auto-stop (#874, iOS rule): a valid ground speed < 30 kt within 5 NM of the destination, only after a fix at ≥ 30 kt was seen (so a round trip or a short hop is not "landed" on the ground at Start), posts `landed: true` once and stops the service; an unsent landing is lost (no retry queue, unlike iOS). It also stops itself at `FlightResponse.trackingWindowEndEpochMs(started = true)`, the latest take-off the server accepts (`MAX_TAKEOFF_DELAY_HOURS`, 6 h) + duration + 2 h. Start is not window-gated on Android. Automatically stopped on `AppStateViewModel.logout()`.
- **`PirepOfflineStore.kt` & `PirepReportingSheet.kt`**: coroutine-safe JSON queue (`pending_pireps.json`) with European airspace bounds validation and idempotent `client_uuid` flush (`PirepFeature.isEnabled = false` by default, matching iOS #661).
- **`PushNotificationManager.kt`**: Android 13+ `POST_NOTIFICATIONS` permission handling, `POST /api/devices` registration with `platform = "android"`, foreground banner suppression when watching the refreshed flight, and tap deep-linking via `PendingNavigation`. (Requires Firebase SDK + `google-services.json` to supply live FCM tokens.)
